# StreamStats

Потоковый анализатор событий из файлов CSV и JSONL.

Программа проверяет события, считает статистику и формирует отчёт
в формате JSON или CSV. Поддерживается обработка нескольких файлов,
фильтрация событий и пропуск ошибочных записей.

## Требования и установка

Требуется Python 3.12 или новее.

Все команды ниже выполняются из папки `lab_02`
в активированном виртуальном окружении.

Установить пакет и инструменты разработки:

```bash
python -m pip install -e ".[dev]"
```

Режим `-e` позволяет изменять код без повторной установки пакета.

## Формат события

Каждое событие должно содержать четыре обязательных поля:

| Поле | Требование |
|---|---|
| `timestamp` | Строка с датой или датой и временем в поддерживаемой записи ISO 8601 |
| `level` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `source` | Непустая строка, не состоящая только из пробельных символов |
| `message` | Строка; пустое сообщение разрешено |

Уровни событий принимаются строго в верхнем регистре.

### Дата и время

Поддерживается дата `YYYY-MM-DD` и дата со временем,
отделённым символом `T` или пробелом.

Время записывается как `HH:MM` или `HH:MM:SS`.
После секунд допускается дробная часть через точку или запятую.

Часовой пояс указывается как `Z`, `+HH:MM` или `-HH:MM`.

Примеры:

```text
2026-10-13
2026-10-13T18:00
2026-10-13T18:00:00Z
2026-10-13 18:00:00
2026-10-13T21:00:00.123+03:00
```

Время с часовым поясом приводится к UTC.
Время без часового пояса считается временем UTC.
Дата без времени означает полночь указанного дня в UTC.

Несуществующие даты и значения, которые нельзя представить
после перевода в UTC, вызывают ошибку временной метки.

### JSONL

Каждая строка файла содержит отдельный JSON-объект:

```jsonl
{"timestamp": "2026-10-13T18:00:00Z", "level": "INFO", "source": "server", "message": "Запуск"}
{"timestamp": "2026-10-13T18:05:00Z", "level": "ERROR", "source": "database", "message": "Нет соединения"}
```

### CSV

Первая строка содержит названия столбцов.
Поддерживаются разделители `,` и `;`.
Разделитель определяется автоматически по заголовку.

Пример с запятой:

```csv
timestamp,level,source,message
2026-10-13T18:00:00Z,INFO,server,Запуск
2026-10-13T18:05:00Z,ERROR,database,"Ошибка, нет соединения"
```

Пример с точкой с запятой:

```csv
timestamp;level;source;message
2026-10-13T18:00:00Z;INFO;server;Запуск
2026-10-13T18:05:00Z;ERROR;database;"Ошибка; нет соединения"
```

Если значение содержит разделитель или перенос строки,
его нужно заключить в двойные кавычки.
Двойная кавычка внутри такого значения записывается как `""`.

Все обязательные столбцы должны присутствовать в заголовке.
Повторяющиеся названия столбцов запрещены.
Количество значений записи должно совпадать с количеством столбцов.

Входные и выходные файлы используют кодировку UTF-8.

## Запуск

Общий вид команды:

```text
python -m streamstats analyze INPUT [INPUT ...] --format FORMAT [OPTIONS]
```

Справка:

```bash
python -m streamstats --help
python -m streamstats analyze --help
```

### Вывод JSON в терминал

```bash
python -m streamstats analyze example/events.csv --format csv
```

Если `--output` не указан, JSON-отчёт выводится в стандартный вывод.

### Сохранение JSON-отчёта

```bash
python -m streamstats analyze example/events.jsonl --format jsonl --output report.json
```

Если выходной файл существует, он перезаписывается.

### Обработка нескольких файлов

```bash
python -m streamstats analyze first.jsonl second.jsonl --format jsonl --output report.json
```

Для всех входных файлов используется формат из `--format`.
Статистика объединяется в один отчёт.

### Пропуск ошибочных записей

```bash
python -m streamstats analyze example/events.jsonl --format jsonl --skip-invalid
```

Неверные записи пропускаются с предупреждением.
Их количество записывается в поле `skipped_lines`.

### Сохранение CSV-отчёта

```bash
python -m streamstats analyze example/events.jsonl --format jsonl --report-format csv --output report.csv
```

`--format` задаёт формат входных файлов.
`--report-format` задаёт формат отчёта.

По умолчанию отчёт имеет формат JSON.
Для CSV-отчёта параметр `--output` обязателен.
CSV-отчёт записывается с разделителем `,`.

## Фильтрация

| Аргумент | Назначение |
|---|---|
| `--level` | Оставить события указанного уровня |
| `--source` | Оставить события с точным именем источника |
| `--since` | Начало периода включительно |
| `--until` | Конец периода включительно |

Пример фильтра по уровню и источнику:

```bash
python -m streamstats analyze example/events.csv --format csv --level ERROR --source database
```

Пример фильтра по времени:

```bash
python -m streamstats analyze example/events.jsonl --format jsonl --since "2026-10-13T18:00:00Z" --until "2026-10-13T19:00:00Z"
```

Начало периода не должно быть позже конца.

Если задано несколько фильтров, событие должно соответствовать всем.
Если фильтры не указаны, учитываются все корректные события.

Проверка входных данных выполняется до фильтрации.
Корректные события, исключённые фильтром, не считаются пропусками.

## Содержимое отчёта

| Поле | Значение |
|---|---|
| `total_events` | Число событий, прошедших фильтры |
| `by_level` | Количество событий каждого уровня |
| `by_source` | Количество событий каждого источника |
| `top_error_sources` | До пяти источников с наибольшим числом событий `ERROR` и `CRITICAL` |
| `first_timestamp` | Самое раннее время среди выбранных событий |
| `last_timestamp` | Самое позднее время среди выбранных событий |
| `skipped_lines` | Число пропущенных ошибочных записей во всех входных файлах |

Источники в топе сортируются по убыванию количества ошибок.
При равенстве используется сортировка по имени источника.

Первая и последняя временные метки определяются по времени,
а не по порядку записей в файлах.

Пример JSON-отчёта:

```json
{
    "total_events": 2,
    "by_level": {
        "DEBUG": 0,
        "INFO": 1,
        "WARNING": 0,
        "ERROR": 1,
        "CRITICAL": 0
    },
    "by_source": {
        "server": 1,
        "database": 1
    },
    "top_error_sources": [
        {
            "source": "database",
            "count": 1
        }
    ],
    "first_timestamp": "2026-10-13T18:00:00+00:00",
    "last_timestamp": "2026-10-13T18:05:00+00:00",
    "skipped_lines": 0
}
```

Если выбранных событий нет:

- общее количество и счётчики уровней равны нулю;
- словарь источников и список источников ошибок пусты;
- временные метки в JSON равны `null`;
- счётчик пропусков сохраняет фактическое количество неверных записей.

CSV-отчёт содержит три столбца:

```csv
section,name,value
summary,total_events,2
summary,skipped_lines,0
by_level,INFO,1
by_level,ERROR,1
by_source,server,1
by_source,database,1
top_error_sources,database,1
```

Это фрагмент отчёта. Полный CSV также содержит остальные уровни
и обе временные метки. Отсутствующие временные метки записываются
пустыми ячейками.

## Обработка ошибок

По умолчанию первая ошибочная запись останавливает обработку.
Сообщение содержит путь к файлу и номер строки.
CLI завершается с кодом `2`.

При `--skip-invalid` программа:

1. Записывает предупреждение уровня `WARNING`.
2. Увеличивает счётчик пропущенных записей.
3. Продолжает чтение.

Неверный заголовок CSV останавливает обработку в обоих режимах.

Запись CSV может занимать несколько физических строк.
Для таких записей сообщается номер последней прочитанной строки.
При незакрытых кавычках повреждённая запись может захватить
оставшуюся часть файла.

Отчёт без `--output` выводится в `stdout`.
Ошибки и предупреждения выводятся в `stderr`.

Коды завершения:

| Код | Значение |
|---|---|
| `0` | Успешная обработка или вывод справки |
| `2` | Ошибка аргументов, данных или работы с файлами |

Собственные исключения:

- `StreamStatsError` — базовая ошибка проекта;
- `UnsupportedFormatError` — неподдерживаемый формат;
- `InvalidEventError` — неверное событие;
- `InvalidTimestampError` — неверная временная метка;
- `CLIConfigurationError` — неверные аргументы командной строки.

## Потоковая обработка

Функции чтения и фильтрации выдают события по одному через `yield`.
Анализатор обновляет статистику за один проход.

Все события не собираются в общий список.
Расход памяти зависит от размера текущей записи
и количества уникальных источников.

## Подключение своего формата

В `streamstats.parsers` находится реестр функций чтения `PARSERS`.

Для добавления или замены формата используется функция:

```python
register_parser(name, parser)
```

Подключаемая функция должна:

- принимать параметры `path`, `skip_invalid`, `stats`;
- читать входные данные последовательно;
- проверять события перед выдачей;
- выдавать словари событий через итератор;
- учитывать режим пропуска ошибок и общий счётчик пропусков.

После регистрации формат доступен через `read_files`.
Регистрация выполняется программно и действует
в текущем процессе Python.

## Структура проекта

|---|---|

| `src/streamstats/models.py` | Проверка событий, обработка времени, счётчик пропусков |

## Дополнительные задания

Реализованы:

- ленивые фильтры по времени, уровню и источнику;
- подключение пользовательского формата через реестр функций;
- сохранение CSV-отчёта без повторного расчёта статистики.

## Проверка проекта

Запуск тестов:

```bash
python -m pytest
```

Проверка кода:

```bash
python -m ruff check .
```

Проверка форматирования:

```bash
python -m ruff format --check .
```

Тесты проверяют валидацию событий, временные метки, оба разделителя CSV,
пустые и повреждённые файлы, режим пропуска ошибок, Unicode,
объединение файлов, фильтры, регистрацию парсера и сохранение отчётов.

Интеграционные тесты запускают CLI в отдельном процессе
и используют временные файлы.
